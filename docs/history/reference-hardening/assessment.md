## Continuation: Paperclip

Paperclip distinguishes finite runs from durable continuation intent and excludes pending interactions from runnable work. ATO already persists the frozen contract, stage, ownership, criteria, manual acknowledgement evidence and cumulative history. Its existing worker lock and explicit invocation are retained; this candidate does not add a polling service or automatically reopen old workflows. A stage finishing successfully is only stage evidence: every overall criterion must independently pass before completion.

The actual gap was repeated identical generated stages after an unchanged overall criterion set and stale state captured before locking. A digest of the generated plan, covered criteria and criterion statuses is now persisted in the stage record; if the immediately preceding generated stage succeeded and the next digest is identical, the workflow stops as blocked with an explanation. This is a conservative observable-progress gate, not a proof that no file changed: partial work may have happened without making a criterion pass. A materially changed plan or criterion disposition is not suppressed. The workflow reloads state after acquiring the existing lock. The fingerprint exists for newly generated stages only; no history is rewritten or migrated. Existing stage creation and the filesystem state store do not form a cross-directory atomic transaction; a process crash during stage creation may leave an orphan directory, and the candidate does not claim exactly-once creation in that window.

## Delivery and recovery: Irrigator

Irrigator uses a durable receipt and exact operation/generation/attempt fencing and refuses replay of uncertain effects. ATO's existing SQLite mailbox has atomic receipt deduplication, immutable route binding, endpoint ownership leases, per-dispatch attempt capabilities and terminal cancellation; its recovery path uses a separate workflow lock and does not resend unknown delivery. These mechanisms are retained and exercised after database reconstruction. Superseding an old binding prevents its late receipt from changing a message on a new binding. No delivery guarantee is claimed across arbitrary external systems.

ATO's mailbox is a local transport and does not itself read a workflow's current generation or act as Irrigator's task mutation mailbox. Correct use requires the host to supersede stale routes and bind the new authority; a route's contract hash is not independently verified as an execution generation. Dispatch attempt tokens fence dispatch completion, and registered session and turn IDs fence observations. Automatic binding migration or a new production integration would be an expansion of this task, so neither is provided. Cancellation and a recorded late receipt do not prove that a remote side effect stopped.

## Adapters: agent-orchestrator

The reference separates readiness, native session identities and authoritative observations. ATO already verifies registered sessions and correlates observation events and ACP outcomes with session and turn. Built-in Claude and Pi are bounded file workers; their presence as worker adapters does not supply coordinator transport, observation, or native resume. The existing doctor now reports code-owned capability names, native resume as unsupported where absent, and readiness as unknown independently of the installed/version check. It does not authenticate or validate a provider. The fixture adapter demonstrates an interface only and does not create real Claude/Pi coordinator support.

## Trace: Vibe Kanban ACP

The reference normalizes tool, approval and error events while retaining tool identity across updates. ATO already has bounded metadata-only trace storage and CLI display; the same tool ID is hashed consistently for all states. We add a metadata-only denied approval event to the ACP path, map unrecognized tool/approval states to `unknown`, and anchor the current summary to the most recent scheduler attempt start so a late earlier-attempt observation cannot replace it. Content, prompt text, credentials and unsafe paths remain excluded; drops and truncation remain visible. Old traces without a start marker retain the legacy fallback and cannot gain identity guarantees they never recorded. Trace is diagnostic, not completion authority. ACP `end_turn`, EOF or process success alone is never trusted native success; independent checks remain required.
