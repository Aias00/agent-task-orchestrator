# ATO 统一入口与任务模型实施拆分

用户已确认整合方向并要求拆分任务。本文记录后续实施顺序和验收条件。源码基线为 `main@86f19d9`，审阅修复在独立分支 `fix/review-findings-20261122@20621c2`，两者尚未合流。

目标版本只公开 `ato`。用户用一个任务 ID 完成提交、观察、停止、继续、回答和验收。Workflow 继续提供阶段执行与独立检查，H1 提供隔离 worktree、只读审阅与有界修复。两者归入同一任务生命周期。

旧命令、参数和公开别名退出新分发。历史任务留在原路径，保留原运行记录和授权证据。新任务使用独立版本命名空间。历史导入和实际生产切换另议。

## 任务与依赖

| 任务 | 前置 | 交付 |
| --- | --- | --- |
| T0 整理实施基线 | 无 | 四项审阅修复的逐项集成与验证记录 |
| T1 定义公开契约 | T0 | 命令、任务规格、状态机、权限与旧能力去向 |
| T2 实现统一任务服务 | T1 | Task/Run 身份、冻结规格、状态与只读查询 |
| T3 接通执行、审阅和恢复 | T2 | 同一执行链、后台启动、STOP、检查、审阅、恢复 |
| T4 接通问答和最终验收 | T3 | 统一收件箱、答复、验收凭据与状态 |

每项形成独立可审查提交。T3 交付后，T4 与 T5 可分开实现，汇入 T6 前联测问答绑定和交接。任务目标以 T7 的完整离线验收为准。

### T0 整理实施基线

- 从实施时核对的 main 创建独立实现分支与 worktree，记录精确提交。逐项检查 `4223d2c`、`291830d`、`0b82bfd`、`20621c2` 是否已进入该基线，补齐仍缺失且适用的修复与回归。设计分支与实现分支分开。
- 验收覆盖宿主操作和审阅复核共享执行权、复核累计记账、Pi TLS 慢响应按实际授权截止控制、初次执行在回归已绿时仍完成冻结的首个工作阶段。
- 记录每项最终来源与全量离线基线计数。若实现分支与原修复发生语义冲突，先复现并明确取舍，再开始接口整合。

### T1 定义公开契约

- 固定 8 个日常操作。管理操作放进 `project`、`agent`、`system`，以分组帮助发现。

  | 命令 | 合约 |
  | --- | --- |
  | `ato run --repo PATH --spec FILE` | 验证并冻结规格，返回任务 ID，默认后台；`--foreground` 等待同一执行流程 |
  | `ato list [--repo PATH]` | 返回当前可见任务，精确按规范化 Git 仓库过滤 |
  | `ato status TASK_ID` | 返回总状态、真实执行、阶段、检查、产物与下一步 |
  | `ato stop TASK_ID` | 写入 STOP 并返回当前停止进度 |
  | `ato resume TASK_ID` | 根据已有记录和恢复检查继续同一任务 |
  | `ato inbox` | 列出当前身份有权读取的待处理事项 |
  | `ato answer REQUEST_ID --answer TEXT` | 对指定请求登记用户的实际答复 |
  | `ato accept TASK_ID --evidence FILE` | 经独立检查并核对授权后，登记特定产物版本的人工验收 |

- 定义带版本的任务规格、状态转移、机器可读输出和退出码。规格包含目标、仓库及基线、范围、阶段与检查、Worker、可选 Reviewer 和人工验收条件。锁定格式与输入验证策略，规格文件只解析数据。
- 逐条登记 [ctask 命令与别名](../tests/fixtures/cli-surface.json) 和 [H1 命令](../hub_cli.py) 的去向。每项标明保留的业务能力、新接口或内部调用点，或删除理由。点明哪些旧名称被现有子进程、通知与 Skill 使用。
- 验收使用状态转移表、角色与操作权限矩阵、旧能力对照表和首版 CLI 契约。终态、清理阻塞、未知交付、等待人工验收分别有明确输出。

### T2 实现统一任务服务

- 以全局任务 ID 为用户标识，Run ID 记录每次执行或恢复。Task 账本保存冻结规格、授权引用和 Run 归属。底层 Workflow 保存阶段、尝试、独立检查和进程证据。任务总状态由上述事实与已绑定的用户决定派生，禁止从查询索引反写执行状态。
- 统一显式 `ATO_HOME` 和默认 `$HOME/.local/share/ato`，厂商原生目录由各自适配器读取。绑定规范化仓库、worktree 和内核记录。现有 `workflow.create` 在传入的 Git 工作树中写入执行记录，任务服务以 Run 绑定定位该记录。
- 验收覆盖跨项目列表、相同任务名称、仓库过滤、规格篡改、并发创建、只读查询与索引重建。创建中断后的记录必须可识别，索引重建禁止产生新执行、改写历史或扩大可见范围。

### T3 接通执行、审阅和恢复

- 使用同一任务启动逻辑服务前台与后台。后台确认执行权与启动回执后报告真实状态。单一 Run 编排持有执行权，复用 Workflow 的阶段检查、所有权租约和进程身份核验。repo/worktree 并发门禁覆盖 Worker、宿主检查和审阅复核。
- 以 H1 的隔离 worktree、共享依赖检查、Reviewer 只读边界与篡改检测为起点。默认校验绑定的基线和工作区。技术审阅失败可进入有界修复，验证与修复沿用原任务规格及累计尝试。
- 验收覆盖后台启动失败、双重启动、检查已绿的首次执行、崩溃后的执行权核验、真实 PID 复用防护、STOP 与进程组清理。清理完成前维持停止中或清理阻塞。显式继续前校验 STOP、执行权和上次结果，沿用 Task ID、累计尝试及授权范围，并记录新的 Run。结果未知或仍有原生进程时拒绝继续，保留恢复证据。

### T4 接通问答和最终验收

- 复用现有请求、答复、去重与权限判断，将问题绑定到任务、规格和必要的 Run 版本。答复按具体请求处理，授权类请求沿用实际授权者和用途校验。进度按查询展示，必要事项与总任务完成依现有策略去重。
- 人工验收绑定规格摘要、产物版本和独立检查证据。正式完成由任务验收事实派生，产物变化需重新检查与验收。重复提交同一决定返回已记录结果。
- 验收覆盖错人答复、跨任务请求、过期回复、重放、Reviewer 审阅通过后仍待用户验收，以及原验收与新产物不匹配。未知投递保持证据并拒绝自动重发。

### T5 接通主控绑定与交接

- 区分用户交互入口、当前主控、实际 Run 所有者和 Reviewer 配置。新对话发起已有任务交接时，校验新旧身份、工程和授权。交接记录携带当前阶段、已用尝试、未决问题及交付证据。
- 执行权与会话绑定各自校验。转交沟通责任时展示原 Run 的真实拥有者。需要接管执行时，先完成旧所有者释放或核验其确已退出，再按现有围栏建立新的执行所有权。
- 验收覆盖项目相同但会话无关、并发交接、旧权限失效、在跑任务交接、停止与交接竞争。切换 Reviewer 后保留 Worker 选择与用户交互绑定。验证和 T4 联用时，未决问题只呈现给核验后的接收方。

### T6 替换 CLI 与分发

- 新分发仅提供一个公开 `ato`。将内部启动、通知和交接读取者绑定到同一封存源码中的私有入口。改造安装、快照资格与切换，替换旧 CLI 冻结测试，合并主控 Skill、快速开始和文档索引。
- 用隔离安装目录与合成状态验证首次安装、移除旧公开入口及升级。升级前检查旧版和新版的活跃任务、observer 和 mailbox；明确记录本次路径、入口的存在性、字节与权限、精确进程身份和封存源码。用同一升级日志恢复原有入口和原 observer，清除升级新增入口。
- 验收覆盖只读诊断、跨版本引用、入口写入中断、observer 失败与重复回滚。旧版本回滚使用原状态命名空间，保留新版账本及工作目录作诊断。任何真实切换前仍需单独确认在跑任务的处置。

### T7 完整离线验收

- 使用临时 Git 仓库、状态目录、安装目录与假 Worker/Reviewer，跑通 `run → status → inbox → answer → accept`，以及 `stop → resume`。验证两个项目能分别查询，同一任务全程只用一个公开 ID。
- 覆盖主控交接、首次执行、最终验收绑定、挂起恢复、未知结果不重放、停止清理、工作区隔离、脱敏、安装与回滚。
- 对全部日常命令与管理分组验证契约。确认旧公开入口退出新分发，私有入口与对应封存源码同源。
- 提供逐任务提交、用例结果、验证环境与尚未覆盖的外部资格。生产激活、历史导入、真实模型与 Provider 验证不属于本轮。

## 共享门禁

每项实施提交运行针对性离线回归。涉及代码的里程碑与最终候选运行 `.venv/bin/python scripts/run_tests.py`、全量 Python 编译、`scripts/check_architecture.py`、分发/元数据/文档检查。最终全量要求零失败、零错误、零跳过。记录实际测试数。

八核心 AST 固定，无新增 vendor 依赖。双向依赖不超过 8 对，且属于当前基线集合。执行权、STOP、累计尝试、独立验收和未知交付不重放是每个任务的行为门禁。实施发现现有接口无法支撑这些约束时，记录最小可复现用例并更新设计边界，避免增加第二套执行权或状态来源。

现行职责边界见 [源码图](source-map.md)、[H1 离线实现](h1-offline-implementation.md)、[用户结案](task-disposition.md) 与 [运行态升级](runtime-upgrade.md)。
