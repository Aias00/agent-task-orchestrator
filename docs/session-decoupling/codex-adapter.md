# Trusted Codex session compatibility

The built-in `agents._CodexAdapter` composes its worker methods with `CodexSessionAdapter`. The registry is code-owned. Core callers go through `session_router`. The native database, CLI receipt, app-server and rollout formats are handled by `ato_adapters/codex_session_adapter.py`. `codex_legacy` remains a forwarding public API, and `recovery.session_path(home, thread)` remains callable by inherited consumers.

Raw UUID workflows retain their identities, directories, question IDs, recovery limits and historical counters. New opaque references require an exact native ID plus project verification. A legacy header with no cwd stays usable for the old interface but cannot satisfy v2 project verification. Legacy actor checks remain compatibility guards, not v2 authentication; environment locators cannot manufacture a user principal. Native load/resume is explicitly unsupported and cancellation is unknown.

The adapter supplies JSON-safe checkpoints to callers. Existing `rollout_offset` and related fields remain readable; they are compatibility cursor fields, not instructions to core modules to parse native data. An observer validates a provided legacy path against the exact current index before reading it. Readers consume bounded complete lines, leave partial lines for later observation, reject truncated cursors, and correlate completed replies to the observed request and turn. Activity uses bounded reverse reading and returns unknown when it cannot establish a lifecycle boundary.

The canonical outbox records dispatching before calling an adapter. A valid exact queue receipt means delivered to native transport, projected as queued by the old APIs. A missing executable is a known no-effect failure. Timeout, uncertain OS errors, nonzero/malformed/mismatched receipts remain delivery_unknown. Neither state is model acceptance or workflow acceptance, and unknown envelopes are never replayed by the outbox.

The registry capability `native_queue_serialization` replaces the bus's Codex-kind branch. It permits releasing a native enqueue slot after the attempt returns, including an ambiguous receipt. This enables distinct queued messages without replaying the unknown envelope. Ordinary streaming adapters retain their slot until their correlated turn is finished. This capability is not inferred from the worker or transport capability.

Creation persists the returned identity before subsequent RPCs, verifies the requested project and sandbox/approval policy, and reads the exact same thread back without loading turns. Writable roots are the existing task/interactions roots plus the explicit contract grant; no additional network grant is introduced. Creation does not start a model turn. Delegation still requires the original acceptance step before its existing dispatcher can start work.

The new suite uses local fixture data only. The bounded foreground compatibility tests and source/test hashes are recorded in `build/session-decoupling/codex-stage-checkpoint.json`. Frozen host acceptance is still required. This stage does not qualify the live daemon, real cloud, real Pi, final migration package or activation, and does not complete the six-step total task.
