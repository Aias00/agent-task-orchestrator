# Observer 执行监控设计

## 目标与边界

Observer 持续采集任务执行证据，将异常与恢复记录放入 `ato status TASK_ID` 的 `watchdog` 字段。监控结论用于主控审阅。任务控制继续通过原有命令执行，采样与通知失败只改变监控诊断。

## 采样

Observer 的通知轮询继续运行。监控使用单个异步只读采样子进程，每个任务至少间隔 60 秒，单次最多 120 秒。超时结束采样进程组。采样按任务轮转，任务版本号相同仍再次检查。采样子进程使用独立只读 Host，核验工作树绑定，复用受限 Git diff 和现有执行身份投影。采样记录与任务版本、Run、STOP epoch 和 binding revision 绑定。发生并发变更时丢弃结果，下一轮重采。

通过当前只读任务投影读取已有任务，支持发布前创建且记录兼容的任务。无法读取的旧记录显示采样失败。查询读取私有监控快照，不初始化目录，不采样，不入队。首次采样前显示 `not_observed`，最后成功采样超过 180 秒显示 `stale`，并保留最后成功时间与采样错误码。

## 规则与恢复

- `EXECUTION_UNVERIFIED`：当前执行投影为 unknown 且最新 Run 尚未 settled，连续两次有效采样才提示。描述为执行身份待核对，避免把无法核验等同于进程已经死亡。
- `REPEATED_ATTEMPTS`：当前步骤至少尝试 3 次且仍未完成，报告步骤与次数。仅凭次数不能证明错误完全相同。
- `DECLARED_SCOPE_CHANGED`：使用用户显式声明的 guardrails 检查实际 diff。路径列表截断时标记证据不完整。范围规则来自已规范化的显式 guardrails。采样失败或不完整时保持此前范围告警，直到完整采样确认恢复。
- `STAGES_INCOMPLETE`：已结束执行仍有明确未交付阶段，或执行投影明确给出 STAGES_INCOMPLETE。
- `UNHANDLED_FAILURE`：任务处于 blocked 或 cleanup_blocked 且无已核验活动执行器。

同一 Run 同一规则保持一个告警，更新最后发现时间和证据。条件消失后写入恢复时间。再次发生创建新 occurrence。仅保留有界的历史记录。未出现 diff 只影响进展观察时间，不单独作为卡死判断。

## 通知

状态中的告警立即可读。有已核验 Codex 提交来源时，复用本地原会话路由与 mailbox 的 FIFO、租约、发送屏障。提醒正文仅含任务 ID、规则代码和查询命令。AGY 尚无定向投递能力时显示 `unsupported`。静默仓库显示 `muted`。无路由显示 `unavailable`。仅新发生的活动告警可以排队，已恢复或版本变化的未发送通知取消。过期消息释放队头。发送结果未知时保留未知回执，重启后也不重新发送。监控复用已存在的业务路由时只接受相同 generation，不推进业务路由版本。Observer 首次遇到启动前就已结束的历史失败时，将告警标记为 \`baseline_only\`，供查询查看。

## 效率数据

展示任务历时、Run 总数、resume/recheck 次数、步骤额外尝试次数、内核累计执行秒数、采样覆盖区间内观察到的等待秒数、最近可观察进展时间。进展由步骤、检查状态与 diff 统计变化定义，同等行数的内容替换可能需要主控查看完整 diff 才能识别。等待统计仅累计相邻成功采样且间隔不超过两倍采样周期的区间。断档不计入。人工实际操作时间与模型 token 成本为 null，提效结论为 `insufficient_baseline`，由后续同类任务基准对比补足。

## 回归覆盖与交付

覆盖两次确认、Run/STOP/binding 变化、恢复与复发去重、读取零写入、采样失败与陈旧、公平调度与超时、显式范围规则、通知去重与未知不重发、AGY 与静默路由、等待统计断档以及任务状态不受监控失败影响。冻结核心与现有 CLI 命令面保持现行边界。

本轮补充离线测试源码，执行结果待用户通知测试后记录。
